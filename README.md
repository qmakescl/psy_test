# psy_test — 심리측정 웹서비스 사전과정 오프닝 데모

> **교육용 시연 코드입니다. 실서비스용 인증 구현이 아닙니다.**
> 강원대학교 대학원 심리학과 ‘심리측정 웹서비스 사전과정’에서 웹의 구성요소(브라우저·서버·DB)와 작동 방식을 보여주기 위해 만들었습니다.

참가자는 휴대폰으로 접속해 가입하고, IPIP 외향성 10문항에 답하고, 내 점수와 우리 반 분포를 봅니다. 진행자는 `/admin.html`에서 응답 수, 시간 추이, 통계분석(α 등)을 강의실 화면에 띄웁니다.

## 구성

| 층 | 파일 | 하는 일 |
| --- | --- | --- |
| 브라우저 | `index.html` · `style.css` · `app.js` | 화면 구조 · 모양 · 동작(서버에 요청 보내기) |
| 브라우저·서버 공용 | `lib/items.js` · `lib/scoring.js` | 문항과 채점. 브라우저가 먼저 계산해 보여주고, 서버가 같은 파일로 다시 계산해 저장 |
| 서버(Vercel 함수) | `api/*.js` (10개) | 가입·로그인·제출·집계. DB 비밀 키는 여기서만 씀 |
| 서버 공용 코드 | `api/_lib/` | 인증, DB 연결, 집계 규칙. `_`로 시작해 주소(API)가 되지 않음 |
| 통계 계산식 | `lib/psychometrics.js` | Cronbach's α, 수정 문항-총점 상관 등 |
| DB(Supabase) | `sql/schema.sql` · `sql/purge.sql` | 표 만들기 · 워크숍 후 전체 삭제 |
| 진행자 화면 | `admin.html` · `admin.js` | 탭 4개: 현황 · 문항별 통계 · 통계분석 · 회차 비교 |

### API

| 요청 | 하는 일 |
| --- | --- |
| `GET /api/config` | 게스트 허용 여부, 현재 회차, 응답 받는 중인지 |
| `POST /api/signup` | 가입(아이디·비밀번호·동의) → 바로 로그인 쿠키 발급 |
| `POST /api/login` · `POST /api/logout` | 로그인 · 로그아웃(참가자·진행자 쿠키 모두 지움) |
| `POST /api/submit` | 응답 10개 제출 → 서버 채점 → 저장 |
| `GET /api/me` | 내 지난 결과(쿠키로 본인 확인) |
| `GET /api/stats` | 현재 회차 분포 — 진행자가 마감한 뒤에만, 5건 이상일 때 |
| `POST /api/admin/login` | 진행자 로그인 |
| `GET /api/admin/stats?view=live\|items\|analysis\|sessions&session=회차` | 진행자 화면 집계 |
| `POST /api/admin/settings` | 게스트 허용 · 회차 코드 · 응답 마감/재개 |

서버는 요청마다 다음을 확인합니다: 상태를 바꾸는 요청(POST)이 이 사이트 화면에서 왔는지(Origin/Referer), 세션이 있고 만료되지 않았는지, 진행자 역할인지, 응답이 1–5 정수 10개인지. 개인 결과와 진행자 응답에는 `Cache-Control: no-store`를 붙입니다.

## 로컬에서 실행

Node.js 22가 필요합니다.

```bash
npm install
npm test        # 채점·통계 기준값·집계 규칙·API 흐름 테스트
npm run dev     # http://localhost:3000 , 진행자 화면은 /admin.html
```

`SUPABASE_URL`이 없으면 **메모리 DB**로 동작합니다(서버를 끄면 자료가 사라짐). 이때 진행자 비밀번호는 `local-admin-only`이고, 샘플 계정 비밀번호는 실행할 때 콘솔에 표시됩니다. 둘 다 로컬에서만 쓰는 값입니다.

## 배포 (Vercel + Supabase 서울)

1. **Supabase**: 새 프로젝트를 Seoul(ap-northeast-2) 리전에 만들고, SQL Editor에서 `sql/schema.sql`을 실행합니다. Project Settings → API Keys에서 비밀 키(`sb_secret_…`)를 확인합니다.
2. **확인**: 공개 키(`sb_publishable_…`)로 표를 조회하면 빈 결과, 쓰기는 거부되어야 합니다(RLS).
3. **Vercel**: 이 저장소를 Import하고 Environment Variables에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `ADMIN_PASSWORD`를 넣은 뒤 배포합니다. `vercel.json`이 서버 함수 실행 지역을 서울(`icn1`)로 지정합니다.
4. **샘플 회차**: 로컬에 `.env.local`(커밋 금지)을 만들고 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `SAMPLE_PASSWORD`를 넣은 뒤 `npm run seed`를 실행합니다.
5. **확인**: 휴대폰으로 가입 → 응답 → 결과까지 해 보고, Vercel 대시보드의 함수 로그에서 실행 지역이 `icn1`인지 봅니다.

환경변수를 바꾸면 다시 배포해야 반영됩니다. 그래서 현장에서 바꿀 값(게스트 허용, 회차 코드, 응답 마감)은 DB `settings` 표에 두고 진행자 화면에서 바꿉니다.

## 샘플 회차(SAMPLE)

실제 참가자에게는 연령대·성별을 받지 않습니다. 대신 미리 만든 가상 자료로 보여줍니다.

- **샘플 계정 5개**(`sample01`–`sample05`): 연령대·성별을 임의로 등록했습니다. ‘가입할 때 기본 정보를 받는 서비스라면 DB에 어떻게 쌓이는지’를 Supabase Table Editor에서 보여줄 때 이 계정들만 띄웁니다. 5명뿐이라 집단별 평균은 항상 ‘5명 미만 집단이 있어 숨김’으로 나옵니다 — 소집단 보호 규칙을 보여주는 장면입니다.
- **합성 게스트 응답 15건**: 통계분석(10건 이상 필요)을 시연할 수 있게 채웠습니다.
- **`data/sample_practice.csv`**: 위 20건으로 만든 실습 파일(합성 자료). 열 이름 끝 `_R`은 역문항(채점할 때 6 − 응답), `score_mean`은 역문항 처리 후 평균입니다. 엑셀·R·jamovi로 α를 다시 구해 진행자 화면 SAMPLE 회차의 값(α 0.93, 역처리 전 −4.07)과 맞춰 볼 수 있습니다. 실제 참가자 응답은 내보내지 않습니다.

## 집계 규칙

1. 로그인 사용자는 사람마다 마지막 응답 1건, 게스트는 건별로 셉니다(단위는 ‘건’).
2. 현재 회차는 진행자가 **응답을 마감한 뒤에만** 분포·평균을 공개합니다. 응답을 받는 동안 집계가 바뀌면, 한 건이 늘 때의 변화로 그 사람의 점수를 거꾸로 계산할 수 있기 때문입니다. 마감하면 새 제출을 받지 않습니다.
3. 분포·평균·문항별 통계는 5건 이상일 때만 보입니다.
4. 집단별 평균은 그 변수에서 한 집단이라도 5명 미만이면 변수 전체를 숨깁니다(일부만 숨기면 뺄셈으로 숨긴 집단을 계산해낼 수 있음).
5. 통계분석은 10건 이상일 때만, 30건 미만이면 ‘불안정’ 표시를 붙입니다. 모든 통계분석 값은 계산 시연용입니다.

## 알려진 한계 (교육용 단순화)

- 비밀번호 찾기가 없습니다(이메일을 받지 않으므로).
- 가입할 때 ‘이미 있는 아이디’라고 알려 주므로 아이디가 있는지 드러납니다.
- 남의 아이디로 일부러 5번 틀려 그 사람을 5분간 잠글 수 있습니다.
- 게스트 응답은 사람을 구분할 수 없어 한 사람이 여러 번 세어질 수 있습니다.
- 번역은 타당화되지 않았고, 결과 해석에 규준이 없습니다.
- 로그인은 원리를 보여주기 위해 직접 구현했습니다. **실서비스에서는 검증된 인증 서비스(Supabase Auth, 소셜 로그인, 학교 통합인증 등)를 쓰세요.**

## 개인정보와 보관

- 이메일·실명·학번·IP 주소·연령대·성별을 받지 않습니다(샘플 계정 제외).
- 워크숍 종료 후 7일 안에 Supabase SQL Editor에서 `sql/purge.sql`을 실행합니다. 모든 표를 비우고 설정을 처음 값으로 되돌리며, 남은 행 수(모두 0)를 출력합니다.
- 응답 데이터, DB 덤프, 실제 키와 비밀번호는 이 저장소에 올리지 않습니다. `.env.example`에는 이름만 있습니다.
- 키가 한 번이라도 커밋되면 지우는 것만으로는 부족합니다. Supabase에서 키를 다시 발급하고 Vercel 환경변수를 바꾼 뒤 다시 배포합니다.
